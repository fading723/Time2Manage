# Time2Manage 2 · 时间有迹

Windows 本地时间记录软件。新版使用浅色侧边栏、圆角卡片、软件分布图、小时热力图和可放大的分钟时间轴。

## 使用

运行 `release/Time2Manage/Time2Manage.exe` 或根目录 `start.bat`。无需安装 Python。请保留整个 `Time2Manage` 文件夹（包括 `_internal`）；EXE 不能单独复制。也可从 Releases 下载 Windows ZIP，解压后运行其中的 `Time2Manage.exe`。

## 自动记录与时间轴

- 预置 Edge、VS Code、Codex、微信、QQ，可添加、编辑和删除软件，也可倒计时识别前台进程。
- 只记录已添加软件处于前台、桌面未锁定、键鼠未超时的使用区间。后台不计时；默认空闲 60 秒后暂停，可设置 5–3600 秒。超时前的宽限时间会计入，阅读或看视频时可调大。
- 以 0.5 秒采样，软件切换边界误差约一个采样间隔。采样中断超过 3 秒不补记（如休眠）。没有记录的时段代表未知，不证明没有工作。
- 时间轴支持全天、6 小时、1 小时视图；左右箭头移动观察窗口；点击任意位置或输入 HH:mm 查看某一分钟的实际软件秒数和专注秒数。悬停查看区间起止时刻。概览和时间轴不展示日记轨道、标记或内容。
- 同一分钟切换过多个软件会分行呈现；前台自动记录通常不在同一瞬间覆盖多个软件，手动专注可以与软件记录重叠。数据结构允许重叠区间。
- **活动覆盖时间**是软件区间与专注区间的并集，重叠部分只计一次；不等同于工作的质量或工作时长。软件累计和专注累计独立展示，不能相加当作工作时间。
- 当天、近一周、自然月视图；点击小时热力图放大时间轴，点击周/月趋势柱切换到当天。软件分布图显示所选范围的累计占比。
- 旧版数据库自动新增明细、日记和复盘表，保留原有每日总量；旧记录无法还原分钟明细，因此旧日的活动覆盖可能缺失，新明细从升级后运行时开始。

## 专注与此刻日记

- 默认 **Ctrl+Alt+F** 开始或结束专注，最小化也有效；专注不依赖软件是否被跟踪或键鼠空闲，休眠间隔不补记。
- 默认 **Ctrl+Alt+J** 唤起原生日记输入框；输入后按 **Ctrl+Enter** 或点击保存。
- 日记保存时记录 Windows 本地日期与时间，精确到秒。在「此刻日记」列表查看内容，也可供 API 复盘使用。
- 两个快捷键都可修改；冲突时提示并保留原快捷键。允许 Ctrl、Alt、Shift、Win 与字母、数字、F1–F12 组合。
- 点击最小化后收起至右下角系统托盘，任务栏不保留窗口按钮；后台记录与全局快捷键继续有效。单击或双击托盘图标重新打开，右键可打开窗口、写日记或退出。图标可能在任务栏的隐藏图标菜单中。
- 关闭窗口可选择后台继续记录、保存并退出或取消；系统托盘不可用时保留普通最小化作为回退。不自动开机启动。

## API 每日复盘

1. 在「设置 → 每日复盘 API」填写基础地址、模型 ID、密钥并保存。支持 `POST /chat/completions` 格式；可填写如 `https://你的服务商/v1` 或完整接口地址。远程用 HTTPS，本机如 `http://127.0.0.1:端口/v1` 可用 HTTP。
2. 点击「测试连接」验证已保存的配置，只发送测试文本。模型 ID 由服务商决定，应用不默认选择或替换模型。
3. 选择日期，进入「每日复盘」点击「预览并生成复盘」。检查目的地址、模型、提示词和完整数据包，再点击「确认发送并生成」。
4. 请求在后台执行，界面和计时保持工作；结果按所选日期保存在本地，可以重复生成并查看各次结果。请求超时为 90 秒，不自动重试。

数据包包括前台/专注区间、每分钟各活动秒数、去重指标、软件总量、带秒级时间戳的日记和明细覆盖范围。发送的是预览时冻结的快照，之后新增内容不会自动混入。

默认提示词要求模型引用时间证据、区分事实与推测、不把聊天或浏览一律视作分心、不编造未记录的活动、不重复累加重叠时间；输出今日概览、节奏、亮点、调整、日记回看和明日小计划。提示词可编辑或恢复默认。

密钥使用 Windows DPAPI 加密，与当前 Windows 账号绑定，界面只显示是否已保存。留空保留原密钥，勾选清除可移除；无密钥的本机模型也可以调用。应用不自动上传数据，只在点击测试或确认生成时连接你配置的 API。API 服务商可能保存收到的记录，发送前可以在应用中检查。

真实服务调用需要用户自己的 API 配置。开发验证使用本机模拟接口，不宣称已验证特定外部服务商或模型。

## 本地数据与备份

数据库位于 `%LOCALAPPDATA%/Time2Manage/usage.sqlite3`。软件记录、区间、日记、复盘及设置均在其中，不收集网页地址、窗口标题或键鼠输入内容。

每次采样事务提交，SQLite DELETE 日志模式与 FULL 同步，已提交记录在主数据库文件内，减少遗漏 WAL 文件导致的数据丢失。旧 WAL 数据库会先合并已提交记录后迁移。启动、每 5 分钟及保存退出时备份至 `backups/usage_日期.sqlite3`。设置页可打开目录或另存完整备份；导出 CSV 包括所选日期的起止区间、秒数和日记。

数据目录由 Windows 当前账号的 Local AppData 位置确定，不依赖 EXE 目录或工作目录；重新打开默认显示当天完整时间轴。日、周、月记录在同一数据库中。启动时检查数据库完整性，异常时保留原文件并报错，不会清空重建。

添加、编辑、删除软件后会立即刷新当前统计及时间轴。删除软件停止记录，并从当前时间轴、统计和新的复盘请求中隐藏；原始历史记录仍在数据库和备份中保留。重新添加同名软件会分配新 ID，不会混入之前的记录。

恢复备份时先退出应用，再替换数据库，同时移走原有的 `usage.sqlite3-wal`、`usage.sqlite3-shm`（如存在）。加密密钥只能由原 Windows 账号解密，换电脑后可能需要重新配置。

## 开发与验证

```powershell
python -m pip install -r requirements.txt
python main.py
python -m unittest discover -s tests -v
python tests/ui_smoke.py
.\build.bat
```

界面集成测试在项目 `build/ui-integration-data` 中使用独立演示数据和本机模拟 API，不向外发送真实记录。演示模式必须指定独立数据目录：

```powershell
python main.py --demo --data-dir build/demo-data
```

代码：`desktop.py`（Windows 窗口、日记、API 调度与本地界面桥接）、`tracker.py`（前台采样）、`windows.py`（Windows API、双快捷键与密钥加密）、`storage.py`（数据库及区间并集）、`review.py`（复盘提示词及接口）、`ui/`（界面和交互）。界面静态资源内嵌在本地窗口，不开启本地 HTTP 服务。

打包入口为 desktop.spec，会排除来自其他工具的 Windows 系统同名 DLL，使用操作系统本身的 ICU 与 API 集。Codex 的部分桌面发行版进程名为 ChatGPT.exe，预置映射同时支持；若你另行使用 ChatGPT 桌面端，可在软件管理中按实际需求调整名称或进程映射。

兼容接口格式参考 [OpenAI Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。
